  Differences found

  1. Sitewide: links are underlined in BS5, weren't in BS3 — fix this

  Every content link (list titles, user names, breadcrumbs, table rows) is now underlined. BS3 relied on the browser/Bootstrap default of text-decoration: none for a (never
  explicitly set in this codebase); Bootstrap 5's reboot CSS sets a { text-decoration: underline } by default, and nothing overrides it.
  - Root cause confirmed via computed style: a {color: var(--bs-link-color); text-decoration: underline}.
  - Scope: every page, every link.
  - Fix: in feder/assets/scss/_variables.scss, add before the bootstrap import takes effect:
  $link-decoration: none;
  $link-hover-decoration: underline;
  - Cost: trivial (2-line SCSS change + make regenerate_frontend). Value: highest — fixes the most visually obvious BS3?BS5 gap across the entire site in one place.

  2. Sitewide: neutral buttons are solid dark gray instead of BS3's white/outline look — needs a decision

  .btn-secondary computes to background: rgb(85,85,85) (the custom $gray/#555) with white text, everywhere a BS3 .btn-default (white bg, gray border, dark text) used to be. This
  isn't an accident — commit 7c5e2d56 ("fix: unify button group styling") deliberately dropped outline buttons in favor of solid ones and made delete actions btn-primary (hence
  "Usun" is now brand-red instead of BS3's amber btn-warning).
  - Scope: 22 templates using btn btn-secondary (all the toolbar/action buttons: Edytuj, Przypisz, Utwórz sprawe, etc.), 0 use btn-outline-secondary.
  - Fix (low cost, no template changes needed): since it's driven by one class, restyle .btn-secondary itself in style.scss to match BS3's .btn-default recipe (white bg / #ccc
    border / dark text, darkening slightly on hover) instead of editing 22 files.
  - Cost: low (one CSS block). Value: high, but this was an intentional recent design choice by a teammate, not an overlooked leftover — worth a quick check-in with rwakulszowa
    before reverting it, rather than just changing it.

  3. Monitoring create/update page: broken breadcrumb (isolated bug) — fix this

  On /monitoringi/.../~edytuj (and the create form), the breadcrumb trail renders as Monitoring sadów apelacyjnychZaktualizuj monitoring — no "/" separator, no spacing, items
  visually merged.
  - Root cause confirmed via DOM inspection: in feder/monitorings/templates/monitorings/monitoring_form.html:8, the active breadcrumb <li> has class="active" but is missing
    breadcrumb-item, so Bootstrap 5's .breadcrumb-item + .breadcrumb-item::before { content: "/" } separator rule never matches it.
  - Scope: only this one template (verified — no other template has the same bare class="active" pattern).
  - Fix: change to class="breadcrumb-item active". One-line change.
  - Cost: trivial. Value: medium (affects 2 of 84 pages, but it's a real, user-visible glitch, not just a color nit).
